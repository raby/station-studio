# Example stations

This directory holds the bundled station templates that ship with
Station Studio. Each is a working playlist generator, copied into
`~/.station-studio/stations/` on first boot.

**Read these in order if you're new:**

| File | What it is | When to fork |
|------|------------|---------------|
| [`starter.json`](starter.json) | Tiny, stateless, two strategies (`weighted` + `jingle`). Demonstrates the slot+strategy mental model on a one-week / one-track-per-hour grid (168 slots). | **Your first station.** Read this end-to-end before anything else; it has just enough complexity to be interesting and no cursor mechanics. |
| [`rebirth-classics.json`](rebirth-classics.json) | One persistent cursor, `window` strategy. 3,010 slots / week, two content pools. Demonstrates how a stateless template plus a single cursor produces a working radio rotation. | **Your second station.** Forking from here gives you a real cursor-driven rotation without the full weekly-emulation surface. |
| [`rebirth-radio.json`](rebirth-radio.json) | Full feature surface: nine persistent cursors with cross-week advance, all five strategies (`jingle`, `weighted`, `mix`, `prev_ref`, `sequential`), reference role. 2,196 slots / week. | **Your third station** (or your reference for "can the engine do X?"). Forking from here is forking a complete production station — be ready for it. |

## Companion files (one per station)

For each station JSON, you may see one or more sibling files:

| Suffix | Purpose |
|--------|---------|
| `.editor.json` | Auto-derived **editor sidecar** (§16.2.1) — section grouping + macro detection for the visualiser. Regenerate via `python -m scripts.derive_sidecar --station NAME.json --out NAME.editor.json` if the template changes. |
| `.pool-manifest.json` | Optional **pool manifest** (§14.36) — declares which iTunes XML files supply which named source pool. Picked up by `make import-weekly-pools manifest=...`. |
| `*.itunes.xml` | **Synthetic companion pool** (only `starter.json` has these). Imported automatically on first boot when the SOURCES table is empty (§16.14 D6). |

## Regenerating the starter pools

The starter station's `STARTER_CONTENT` (50 tracks / 10 artists) and
`STARTER_JINGLES` (5 jingle-genre tracks) pools are generated
deterministically by a small script — fix a typo or change the track
count in one place, then:

```bash
make refresh-starter-pools
```

The XML files in this dir are regenerated byte-identically. The
script lives at [`scripts/generate_starter_pools.py`](../scripts/generate_starter_pools.py)
if you want to read it.

## Adding a new station

Drop `your-station.json` here. On next `station-studio serve`, the
auto-seed lifespan picks it up + creates the row. See
[CONTRIBUTING.md](../CONTRIBUTING.md) for the template grammar
contract and the slice pattern for proposing new station shapes.
